# Островок AI v7 — Geo Agent

## Реализованные сценарии

1. **OSM-кандидаты координат.** Overpass ищет объекты `tourism=hotel` в пределах пилотного района. Система сопоставляет название/адрес, сохраняет OSM ID, ссылку, score, геометку, исходные теги и время. Совпадение не подтверждает само себя. Ответственный сотрудник выбирает правильный объект.
2. **Проверенные оператором координаты.** После подтверждения в `hotels` записывается `osm_manually_reviewed`, а соответствующий OSM-кандидат остаётся в базе как доказательство. При изменении геометрии этого же OSM ID требуется новое подтверждение. Ранее полученные геофакты инвалидируются.
3. **Расстояние до берега.** Коннектор Overpass возвращает координаты `natural=coastline`. Алгоритм вычисляет расстояние **по прямой** (при PostgreSQL — PostGIS, при SQLite — локальный расчёт). Это не пешеходный путь.
4. **Маршрут до пляжа.** Overpass ищет обозначенные пляжи (`natural=beach` или `leisure=beach`), исключает помеченные `private/no`. Valhalla возвращает маршрут в режиме `pedestrian`. Рассматриваются максимум три ближайших найденных объекта; выбирается маршрут с наименьшим временем. Значения `beach_route_m` и `beach_walk_minutes` сохраняются со ссылками на исходные объекты и метод расчёта.
5. **Переобход и изменения.** `python -m intelligence.refresh` выбирает отсутствующие/устаревшие значения по TTL, запускает новые задания и пишет изменения в `audit_events` (`fact.changed`). Все исторические свидетельства сохраняются, а предыдущий результат того же вычислителя не считается независимым противоречием.
6. **Telegram Mini App.** В карточку добавлена секция «География и путь к пляжу»: отдельные показатели для прямого расстояния и пешеходной сети, статус источника, ссылка на OpenStreetMap.

## Принципиальные ограничения достоверности

- Координаты со статусом `third_party_reported` не становятся «подтверждёнными» автоматически.
- Наличие точки `natural=beach` **не гарантирует действующий открытый вход**, а центр полигона не равнозначен точке прохода. Поэтому маршрут имеет статус `estimated` и явное предупреждение о доступности пляжа. Для проверки доступа понадобится дополнительный слой пляжных входов и/или информация от отельера.
- Время берётся из Valhalla, а не оценивается делением расстояния на скорость пешехода. Это моделируемое время на карте, не гарантированное время похода.
- Ошибка, timeout или неполный ответ API не создают нулевые/выдуманные значения.
- Без сетевого доступа свежие результаты не генерируются. Встроенные офлайн-свидетельства остаются отдельно от live-источников.
- OSM не является официальным подтверждением названия/входа/услуги отеля. Нужна сверка с официальной страницей.

## Запуск без Docker

```bash
sh start.sh
```

На Windows: `start.ps1`. После этого Mini App доступно на `http://127.0.0.1:8090`, документация API — `/docs`.

Для **реальных** источников необходимо разрешить live-запросы перед стартом:

```bash
export OSTROVOK_LIVE_SOURCES=true
sh start.sh
```

Локальные права администратора действуют только при `OSTROVOK_ALLOW_LOCAL_WRITE=true`, когда нет `OSTROVOK_API_TOKEN` и входящее соединение пришло с `127.0.0.1`/`::1` (для тестов — `testclient`). Не публикуйте такой сервер в интернет. Для Docker всегда используйте Bearer-токен сервиса.

## Операции — последовательность

Для примера использован ID гранд-отеля «Жемчужина» в учебном каталоге: `4b8ec4d1-edc1-59c0-ab4a-ed2c62f209a4`.

**1. Найти кандидатов OSM:**

```bash
curl -X POST http://127.0.0.1:8090/api/v2/intelligence/hotels/4b8ec4d1-edc1-59c0-ab4a-ed2c62f209a4/geo/discover
```

Результат содержит OSM ID, координаты, источник, атрибуты и `score`. **Вручную откройте OSM-ссылку, проверьте адрес, название и реальное положение здания.** Если список пуст или неоднозначен, не подтверждайте случайный вариант.

**2. Подтвердить проверенный кандидат:**

```bash
curl -X POST http://127.0.0.1:8090/api/v2/intelligence/hotels/4b8ec4d1-edc1-59c0-ab4a-ed2c62f209a4/geo/approve \
  -H 'Content-Type: application/json' -d '{"candidate_id":"ВСТАВЬТЕ_ID_ИЗ_ОТВЕТА"}'
```

ID должен быть 32-символьной шестнадцатеричной строкой из ответа `/geo/discover`.

**3. Запустить исследование:**

```bash
curl -X POST http://127.0.0.1:8090/api/v2/intelligence/jobs/enrich \
  -H 'Content-Type: application/json' -H 'Idempotency-Key: sochi-v7-first-georun' \
  -d '{"hotel_id":"4b8ec4d1-edc1-59c0-ab4a-ed2c62f209a4", "feature_keys":["coast_straight_m","beach_route_m","beach_walk_minutes"],"mode":"live"}'
```

Запрос поставит работу в очередь `BackgroundTasks`. Получите `job_id`, проверьте `GET /api/v2/intelligence/jobs/{job_id}`, затем откройте карточку отеля и доказательства. При повторном исследовании используйте новый `Idempotency-Key`.

**4. Проверить изменение и историю:**

```text
GET /api/v2/intelligence/hotels/{hotel_id}/geo/status
GET /api/v2/intelligence/hotels/{hotel_id}/changes
GET /api/v2/intelligence/hotels/{hotel_id}/evidence?feature_key=beach_walk_minutes
```

Маршруты `/geo/discover`, `/geo/candidates`, `/geo/approve` и `/changes` доступны только администратору. `/geo/status` доступен гостю и не позволяет изменять данные.

## Периодическая актуализация

Сначала посмотреть список задач без вызова внешних сервисов:

```bash
python -m intelligence.refresh --dry-run --limit 3
```

После включения `OSTROVOK_LIVE_SOURCES=true` выполнить один проход:

```bash
python -m intelligence.refresh --live --limit 2
```

Для явного переобхода одной гостиницы:

```bash
python -m intelligence.refresh --live --force --hotel-id 4b8ec4d1-edc1-59c0-ab4a-ed2c62f209a4 --limit 1
```

Это **CLI-задача**, а не работающий в фоне планировщик. Для повторов по расписанию подключите cron/Kubernetes CronJob/Railway cron с разумным интервалом. Публичные Overpass/Valhalla требуют соблюдения fair-use и могут временно быть недоступны.

## PostgreSQL / PostGIS

Новая таблица: `sql/003_geo_candidates.sql`. Для миграции установленного PostgreSQL выполните:

```bash
python -m intelligence.database
```

Команда также применяет базовую PostGIS-схему и `002_nullable_coordinates.sql`. Рекомендуется предварительный бэкап базы. В Docker это вызывается стартовой командой сервиса.

## Проверки

```bash
python -m pytest -q
node --check web/app.js
```

Тесты используют поддельные HTTP-ответы Overpass/Valhalla, независимо от сети. Live-запросы и SQL-миграция на запущенном PostGIS требуют проверки на окружении с доступом к API и PostgreSQL.
