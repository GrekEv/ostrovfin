# Операторская панель и городской импорт · v9

## Сценарий запуска

В режиме локальной демонстрации запустите API с `OSTROVOK_ALLOW_LOCAL_WRITE=true` и откройте `/operator` с localhost. По умолчанию этот флаг выключен. В серверном режиме потребуется токен `OSTROVOK_API_TOKEN`. Панель держит введённый токен только в оперативной памяти страницы и не сохраняет его в `localStorage` или cookie. Размещайте админку только через HTTPS и ограниченный доступ (VPN/прокси).

## Импорт

Скопируйте `data/city_notice_template.csv` и замените учебные значения настоящими публикациями. Каждая строка обязана содержать постоянный идентификатор записи у провайдера, HTTPS-ссылку на исходный документ, категорию (`construction`, `road_closure`, `festival`), координаты, даты действия и описание. Ограничение пилота: Сочи и Адлер.

```bash
python -m intelligence.city_import data/city_notice_template.csv
python -m intelligence.city_import data/city_notice_template.csv --apply
```

Первый вызов предварительно создаёт локальную демо-БД, если её не было, но не добавляет городские записи. Второй сохраняет только `pending`-кандидатов. Любое исправление текста, дат или координат приводит к новой версии с тем же `provider/source_reference`. Старая опубликованная версия остаётся активной до одобрения новой. После одобрения новой версии старая получает `superseded`. Отклонение исправления оставляет ранее одобренную версию доступной.

Публичное поле `status: unknown` при отсутствии найденных уведомлений сохраняется — неполные реестры не позволяют утверждать, что работ нет.

## Источники

Подтверждён существующий нормативный порядок публикации разрешительной документации и ссылка на официальный сервис незаконного строительства Краснодарского края. Универсального публичного API с точными датами фактических работ и геометками для Сочи не подтверждено. Реестр разрешений сам по себе **не является** сведением о действующей стройке в конкретные даты. Не конвертируйте его автоматически в `construction`.

Стартовая точка аудита: https://pgu.krasnodar.ru/illegal-construction. Проверяйте правила доступа, геопривязку и лицензию каждого конкретного источника перед импортом.

## Операционная проверка

1. Импортируйте валидный CSV, затем откройте `/operator` и список ожидающих городских уведомлений.
2. Откройте оригинал и сравните дату, координаты и содержание с карточкой.
3. Одобрите запись или отклоните её. До одобрения она отсутствует в публичном поиске.
4. Исправьте текст в CSV, импортируйте снова, затем одобрите новую ревизию.
5. Проверьте, что предыдущая ревизия отмечена как `superseded`, а в журнале аудита остались обе операции.
6. Проверьте план обновления геофактов без запуска сетевых запросов.

## Ограничения

Нет верифицированного API городских событий Сочи, расписания автоматической доставки уведомлений, реальных административных пользователей и доказательства отсутствия строительных работ. Импорт производится вручную, а обновление сетевых источников требует включения live-режима на сервере.

## Опциональная загрузка по HTTPS

При наличии **проверенного оператором** официального CSV/JSON-фида можно настроить фиксированный адрес на сервере:

```dotenv
OSTROVOK_LIVE_SOURCES=true
OSTROVOK_CITY_FEED_URL=https://example.gov.ru/data/sochi-notices.csv
OSTROVOK_CITY_FEED_HOSTS=example.gov.ru
```

Адрес выше — только шаблон, не подтверждённый источник. URL запрещено задавать через публичный API. Хост должен присутствовать в явном allowlist. Редиректы, небезопасный HTTP, IP-адреса и нестандартные порты запрещены; размер ответа ограничен 2 МБ, записи должны пройти ту же схему валидации, что и локальные файлы.

```bash
python -m intelligence.city_fetch
python -m intelligence.city_fetch --apply
```

Для периодического обновления на собственном сервере настройте cron/systemd timer с командой `python -m intelligence.city_fetch --apply`, например раз в сутки. Каждая новая редакция всё равно требует ручного одобрения; никаких автоматических заявлений об отсутствии стройки. Проверку успешности, журнал ошибок и оповещения о падении задания настраивает оператор.
