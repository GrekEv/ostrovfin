# Островок AI v6 — реальный пилот

## Пользовательские изменения

- Пять реальных объектов: Жемчужина, Mercure, Pullman, SEA GALAXY и Radisson Collection Paradise Resort & Spa.
- Сведения об условиях проживания с питомцами, балконах, строительном годе и объявлении Mercure о плановом ремонте импортируются из заранее подготовленного набора официальных источников.
- Адреса и URL источников видны в API; версии датированы 26.10.2026 и автоматически устаревают по TTL.
- Вымышленные отели отключены по умолчанию; их можно добавить через `OSTROVOK_DEMO_SEED=true` и показывать отдельным переключателем.
- В клиентском интерфейсе предупреждение о ремонте отделено от обязательных условий поиска.
- Отсутствующие координаты хранятся как `null`. Ни `0,0`, ни время пешком не выдумываются.

## Для разработчиков

- `data/official_hotels.json`: подготовленные источники, URL, извлечённые значения и редакторские оговорки.
- `POST /api/v2/intelligence/hotels/{id}/coordinates`: защищённая запись координат с URL и аудитом.
- `sql/002_nullable_coordinates.sql`: разрешает ранее запрещённые `NULL` в геокоординатах.
- `get_profile`: оценивает актуальность на чтении и возвращает `expires_at`.
- `get_evidence`: возвращает `source_note` с контекстом утверждения.
- `intelligence/probe.py`: выбирает только отель с имеющимися координатами.
- Dockerfile включает каталог `web/`, локальные скрипты запуска исключают автоматический расчёт на синтетической геометрии.

## Проверка

```bash
python -m pytest -q
node --check web/app.js
```

Отдельный интеграционный тест PostgreSQL/PostGIS остаётся пропущенным без реального инстанса. Live-запросы к Overpass не проверены в этой среде, поэтому выпуская прототип, нельзя рекламировать 5 отелей как автоматически исследованные в реальном времени. У них есть отдельно собранные официальные свидетельства.

## Следующие инженерные задачи

1. Подтвердить координаты четырёх объектов через OSM ID или прямые геоданные и собрать офлайн-снимок береговой линии с ODbL attribution.
2. Реализовать пешеходную маршрутизацию до входа на пляж вместо геометрической прямой.
3. Организовать ревалидацию официальных страниц с изменениями, кешированием, limit/retry и журналом сверки.
4. Запустить миграцию и интеграционные тесты PostGIS в Docker.
5. Объединить компонент с оригинальным Go API, когда исходники репозитория доступны в среде разработки.
