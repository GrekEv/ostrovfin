# Островок AI · v9

Telegram Mini App и Intelligence Engine для исследования характеристик отелей.

**Прототип.** Не является сервисом бронирования. Исходный репозиторий `GrekEv/ostrovok` не изменён. Интеграция с его `travel_cards` и `user_swipes` остаётся отдельной задачей. Новые источники запрашиваются по явной команде; готовых подтверждённых OSM-координат для всех пяти отелей в архиве нет.

## Новое в v9: служебная проверка и версионированные городские данные

- **Панель `/operator`:** обзор очередей, проверка городских записей, привязок зданий, фотографий и OSM-кандидатов. Содержимое доступно только с серверной административной авторизацией; API-токен, введённый оператором, хранится только в памяти страницы.
- **Импорт CSV/JSON:** `python -m intelligence.city_import data/city_notice_template.csv` проверяет данные, `--apply` записывает их в статусе `pending`. Синтетический файл-шаблон не является реальным городским источником.
- **Контроль редакций:** исправленный документ не вытесняет одобренную публикацию до повторной проверки. После одобрения новой версии предыдущая помечается `superseded`; отклонение новой оставляет прежнюю видимой.
- **Защищённый feed-загрузчик:** `python -m intelligence.city_fetch --apply` использует только заранее заданный сервером HTTPS-URL с allowlist хостов. Без разрешённого реального источника импорт остаётся ручным.
- **Аудит:** операторская панель отображает историю действий и предварительный план актуализации геохарактеристик; фактический обновляющий job по-прежнему требует явного запуска.

Быстрый локальный запуск `./start.sh`, затем клиент `/`, операторская панель `/operator`, API `/docs`. Внешние муниципальные API и PostGIS в этой среде не прогонялись; импорт из проверенных файлов работает и покрыт тестами.

Инструкция «с нуля»: [docs/START_V9.md](docs/START_V9.md). Сценарий работы оператора: [docs/V9_CITY_SOURCES.md](docs/V9_CITY_SOURCES.md). Это отдельный модуль поверх v8, не прямая интеграция с Go-репозиторием.

## Что работает

- Поиск на русском с объяснимым сопоставлением условий и отдельной трактовкой пешего маршрута.
- Клиентская зона: карточки, подробные факты, доказательства, избранное, история запросов, сравнение до трёх объектов, профиль и справка.
- Пять реальных объектов с адресами и ссылками на официальные сайты; сведения о животных, балконах и уведомлении о ремонте являются курированными заявлениями источников. Три вымышленных отеля подключаются **только по явному запросу**.
- Реестр из 17 характеристик, provenance и Evidence Store, выявление конфликтов.
- Коннекторы Overpass (координаты, берега, пляжи), Valhalla (маршруты пешехода) и Wikidata; live-запросы включаются явно.
- Проверка OSM-кандидатов оператором, сохранение истории геоданных, журнал изменений и CLI-переобход просроченных признаков.
- Геоблок внутри карточки с отдельным статусом достоверности, ссылкой на OSM и предупреждением о доступности пляжа.
- Вопросы отельеру → извлечение значений → подтверждение → запись фактов.
- Проверка Telegram Mini App `initData` на сервере с защитой от просроченных/поддельных подписей и привязкой отельера к одному объекту.
- Поддержка SQLite demo и PostgreSQL/PostGIS при отдельной миграции.

## Быстрый запуск, без Docker

Требуется Python 3.11+:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn intelligence.api:app --host 127.0.0.1 --port 8090
```

В Windows активация окружения: `.venv\Scripts\activate`.

Откройте `http://127.0.0.1:8090/`. API Swagger: `http://127.0.0.1:8090/docs`.

Пример поиска: «Тихий отель с видом на закат и собакой 12 кг». Затем изучите одну из карточек, сохраните два отеля, откройте «Сравнить». Раздел «Кабинет» содержит справку и информацию о качестве.

### Как посмотреть цикл отельера

При запуске `./start.sh` (или `start.ps1`) разрешены только локальные демозаписи; **для активации кабинета отельера** установите `OSTROVOK_DEMO_SEED=true` до первого запуска и используйте отдельную чистую демо-БД. При ручном запуске предварительно задайте `OSTROVOK_ALLOW_LOCAL_WRITE=true`; никогда не включайте этот режим на внешнем сервере. Затем откройте **Кабинет → Кабинет отельера**. В кабинете вымышленного отеля нажмите «Создать демонстрационный вопрос», введите «С собаками можно до 12 кг, доплата 1500 рублей за ночь. С кошками нельзя». Проверьте выделенные поля, подтвердите и повторите поиск. Ответ относится к **вымышленному** отелю.

Локальный деморежим намеренно ограничивает мутации адресом loopback. Нельзя публиковать его в интернете как production.

### Демо-данные

По умолчанию загружаются пять реальных объектов. Данные из официальных источников зафиксированы в `data/official_hotels.json` и отмечены как курированные офлайн, а не как live-запросы.

Для включения трёх вымышленных объектов установите `OSTROVOK_DEMO_SEED=true` **до первого запуска**, затем отметьте переключатель под поиском. Вымышленные данные маркированы как `synthetic_fixture`. Они **не считаются проверенными фактами**.

Для отключения синтетических объектов задайте `OSTROVOK_DEMO_SEED=false` перед первым запуском. Для чистого сброса локального демо остановите приложение и удалите `data/intelligence-v9.sqlite3`. Не удаляйте производственную БД.

## Новое в v8: городские события, Wikidata и Commons

- В поиске появились даты поездки. Подтверждённые оператором объявления о строительстве, перекрытиях и фестивалях появляются как **предупреждения со ссылкой на источник**, если пересекаются по датам и географии. Отсутствие записей не означает отсутствия стройки.
- Для истории зданий реализована административная привязка QID к конкретному физическому зданию, инспекция Wikidata и использование проверенной идентичности в сценарии определения года постройки. Описание Wikidata не превращается автоматически в исторический факт.
- Добавлен поиск геопривязанных фотографий на Wikimedia Commons, сохранение кандидатов и ручная модерация. Фото с улицы не выдаётся за подтверждение вида из номера.
- Все три сценария используют существующие источники, аудит и отдельные защищённые административные API. SQL-модели добавлены миграцией `sql/004_research_v8.sql`.

**Подробные сценарии для разработчика и проверяющего:** [docs/V8_RESEARCH_AGENTS.md](docs/V8_RESEARCH_AGENTS.md). Новые городские события не загружаются автоматически и не выдумываются; при отсутствии реального источника статус `unknown`.

## Геоагент v7: реальные маршруты и актуализация

Подробная инструкция для **поиска координат в OSM, подтверждения объекта, запроса настоящих маршрутов Valhalla, просмотра происхождения расчёта и переобхода устаревших значений**: [docs/V7_GEOAGENT.md](docs/V7_GEOAGENT.md).

Для просмотра задач переобхода без сетевых запросов:

```bash
python -m intelligence.refresh --dry-run
```

Настоящая маршрутизация требует `OSTROVOK_LIVE_SOURCES=true`, доступных Overpass и Valhalla, а также координат отеля. Новый источник **не подтверждает себя автоматически**: OSM-кандидаты координат должны быть проверены оператором. Система не выдаёт точку пляжа за проверенный вход, а модельное время маршрута — за гарантию.

## Telegram: безопасный кабинет отельера

1. Создайте бота через BotFather, укажите HTTPS-URL приложения для Mini App.
2. Установите `TELEGRAM_BOT_TOKEN` на **сервере**, не в JS.
3. Укажите привязку Telegram ID к UUID гостиницы в `OSTROVOK_HOTELIER_BINDINGS_JSON`, например `{"123456789":"7914497a-b266-5276-bc74-b2be12a96e12"}`.
4. Установите `OSTROVOK_MODE=production`, сервисный токен и HTTPS reverse proxy.
5. Браузер отправляет подписанные Telegram `initData` в `Authorization: tma ...`. Backend сверяет подпись, дату и принадлежность отеля.

Пользователь без роли отельера не видит служебное меню и не может изменять данные. Сервисный API-токен браузеру не выдаётся. В production прямой `Bearer` для операций отельера по умолчанию запрещён.

**Внимание:** проверка подписи реализована, но промышленное размещение также требует rate limiting, журналирования security-событий, настройки прокси и проверки бот-меню в Telegram. Ещё не проводился внешний security audit.

## Тесты

Версия v9 дополнительно проверяет импорт, безопасную загрузку источника, очередь модерации и смену версий. Версия v8 проверяет сценарии по датам поездки, в том числе отсутствие события, неверный интервал, ручное подтверждение записи, работу с QID, фильтрацию Commons и права на административные операции. Интеграционный тест PostgreSQL пропускается без сервера.


```bash

```

## Ограничения

Реальные обращения к OSM/Wikidata/Valhalla не подтверждены в текущей среде; пилотная выборка из 20 реальных гостиниц не сформирована. Пешеходный роутинг реализован в коде, но начинает выдавать значения только после успешного реального запроса; без него условие «10 минут пешком» остаётся неподтверждённым. Нет настоящих цен и доступности. Оригинальный Go API не объединён с этим архивом.

## История: изменения v6

- Список из **5 настоящих гостиниц**, утверждения по правилам размещения питомцев и балконам с URL и датами проверки. Подробности: [docs/REAL_SOURCE_AUDIT.md](docs/REAL_SOURCE_AUDIT.md).
- Уведомление Mercure о ремонте **не** означает, что работы идут сейчас; перед поездкой проверяйте текущий статус у отельера.
- Учебные гостиницы отключены по умолчанию, клиент включает их явно.
- Неизвестные координаты допускаются как `null`: геоагент возвращает `needs_coordinates`, а не подставляет нули.
- Защищённый `POST /api/v2/intelligence/hotels/{id}/coordinates` сохраняет URL происхождения координат, сбрасывает ранее вычисленные итоговые геофакты и фиксирует аудит.
- TTL по типам характеристик рассчитывается при чтении и переводит старые значения в `stale`.
- Для чистого локального запуска v6 используется отдельный файл БД. Для существующей PostgreSQL-схемы примените `sql/002_nullable_coordinates.sql` перед импортом. 
- В настоящей среде внешние HTTP-запросы к OSM и рабочий Docker не проверены; коннекторы остаются подготовленными, но не подтверждёнными live-тестом.

### Быстрая проверка

1. Откройте `/`, выберите «🐾 С питомцем». Mercure будет подходить по собаке до 12 кг, Radisson — нет (лимит 8 кг).
2. В карточке Mercure изучите опубликованное уведомление о ремонте и URL в доказательствах.
3. Переключитесь на «10 минут пешком»: система не выдумывает время маршрута.
4. Отдельно включите учебные отели, если хотите увидеть полноту демоданных.

**Запуск и безопасность.** Docker-образ включает `web/` и отдаёт интерфейс на `/`; операции записи в Docker требуют серверных полномочий. Для локальной демонстрации кабинета отельера рекомендуется `./start.sh` или `start.ps1` на `127.0.0.1`, где включается локальная авторизация только для разработки. `OSTROVOK_ALLOW_LOCAL_WRITE=true` не используйте при пробросе порта наружу или за reverse proxy.
