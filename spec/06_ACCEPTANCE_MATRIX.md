## 2. Метрики — формулы

- **Coverage:** количество пар `(hotel_id, feature_key[, context])` с пригодным для указанной даты resolved value / количество ожидаемых пар; перечень «обязательных для пилота» должен быть закреплён.
- **Verified share:** доля наблюдений с `verified` среди соответствующего набора; отдельно от общей coverage.
- **Precision (binary claims):** TP/(TP+FP), где эталон вручную размечен; нет TP+FP — значение `null`.
- **Accuracy (categorical):** доля правильных предсказанных значений на размеченном наборе; missing/unknown учитываются отдельно.
- **Abstention rate:** доля случаев, где вернулся unknown/stale вместо неподтверждённого ответа.
- **Conflict recall:** обнаруженные искусственно заложенные конфликты / все заложенные конфликты.
- **Hotelier escalation rate:** количество уникальных `(hotel_id, feature/context)`, потребовавших вопроса / количество исследованных пар.
- **Freshness:** доля опубликованных значений, удовлетворяющих TTL признака и актуальности источника.
- **Provenance completeness:** доля опубликованных утверждений, имеющих source ID, время, method и контекст; цель 100%.

Метрики считаются отдельно для `demo_synthetic`, `snapshot_real`, `live_real`. Они не смешиваются при презентации. Число тестовых объектов, характеристики и знаменатели всегда печатаются рядом с оценкой.

## 3. Этапные ворота (go/no-go)

**Gate 1 / после аудита.** Каталог и API исходного репозитория сопоставлены; список источников с проверенными URL/лицензиями и решением `usable | conditional | unavailable` готов.

**Gate 2 / после storage.** Схема PostGIS мигрирует «с нуля»; 20 отелей и evidence snapshots воспроизводятся offline.

**Gate 3 / после connectors.** 3 подключённых семейства источников реально отдают данные, работают кеш и retry; маршрут/георасчёт покрыт тестами.

**Gate 4 / после agents.** Hotelier dialogue и conflict resolver проходят AT-11–AT-15, исходные тексты не теряются.

**Gate 5 / релиз.** Все критические AT-01, 03, 05, 07, 08, 11, 13, 15, 16, 19, 21, 22, 24 зелёные; расширенный отчёт quality сохранён.

## 4. Приоритет задач

**P0:** каталог + доказательства + geo + реальные коннекторы + конфликт + свободный ответ + защищённый API + offline seed + тесты.

**P1:** новые признаки из YAML, TTL refresh, метрики на независимой разметке, интеграция с Go chat, добротная Data Inspector-консоль.

**P2:** архитектурная история здания с более глубоким entity linking, advanced view analysis, Mapillary, фестивали/перекрытия при наличии проверенных пригодных фидов.
